Build this four-lane browser rhythm game with generated original music and falling notes. Every number below is a given value to write into the code as-is; none of them needs checking or deriving.

RECORDS: NOTE, PLAYER, SONG, RUN, AUDIO EVENT, INSTRUMENT.

NOTE: each note has lane 0 to 3, time in s from 0.0 to 60.0, duration in s 0.0 for a tap or 0.4 to 0.8 for a hold, state one of unhit, hit, holding, held, missed starting unhit, judgment one of none, perfect, good, ok, miss starting none, points 0, 30, 60, 100 starting 0, holdBonus 50, position 1.0.

PLAYER: level 1, unlockedSongs 1, clearedSongs 0, totalScore 0, bestAccuracy 0.0 percent, totalNotes 0, totalHits 0.

SONG: id 1 to 8, seed integer, bpm beats/min, beat s, length s, difficulty 1 to 5, unlockScore points, status one of locked, ready, active, cleared, failed starting locked except song 1 ready, bestScore 0, bestAccuracy 0.0 percent. The fixed roster is: song 1 seed 10101 bpm 84 beat 0.714 length 32 difficulty 1 unlockScore 0; song 2 seed 20202 bpm 92 beat 0.652 length 36 difficulty 2 unlockScore 8000; song 3 seed 30303 bpm 100 beat 0.600 length 40 difficulty 2 unlockScore 16000; song 4 seed 40404 bpm 108 beat 0.556 length 44 difficulty 3 unlockScore 26000; song 5 seed 50505 bpm 116 beat 0.517 length 48 difficulty 3 unlockScore 38000; song 6 seed 60606 bpm 124 beat 0.484 length 52 difficulty 4 unlockScore 52000; song 7 seed 70707 bpm 132 beat 0.455 length 56 difficulty 4 unlockScore 68000; song 8 seed 80808 bpm 140 beat 0.429 length 60 difficulty 5 unlockScore 86000.

RUN: songId 1 to 8, clock 0.0 s, leadTime 1.5 s, score 0, combo 0, maxCombo 0, multiplier 1, health 100, accuracy 100.0 percent, status one of ready, active, cleared, failed starting ready, perfectNotes 0, goodNotes 0, okNotes 0, missNotes 0, totalNotes 0.

AUDIO EVENT: time 0.0 to 60.0 s, instrument one of kick, snare, hat, bass, lead, pitch semitones -12 to 12, length 0.02 to 0.5 s, gain 0.0 to 1.0, played false.

INSTRUMENT: name, wave one of sine, square, saw, noise, baseHz, decay s, gain. The fixed roster is: kick wave sine baseHz 60 decay 0.12 gain 0.8; snare wave noise baseHz 1800 decay 0.08 gain 0.5; hat wave square baseHz 6000 decay 0.03 gain 0.2; bass wave saw baseHz 55 decay 0.25 gain 0.35; lead wave square baseHz 440 decay 0.18 gain 0.25.

SYSTEMS: CONTROLS, SEEDED GENERATOR, MUSIC SYNTH, NOTE JUDGE, SONG FLOW, PROGRESSION.

CONTROLS: when W keydown or Up keydown, a lane 0 press starts; when W keyup or Up keyup, lane 0 releases; when A keydown or Left keydown, lane 1 press starts; when A keyup or Left keyup, lane 1 releases; when S keydown or Down keydown, lane 2 press starts; when S keyup or Down keyup, lane 2 releases; when D keydown or Right keydown, lane 3 press starts; when D keyup or Right keyup, lane 3 releases; when a touch starts in the leftmost quarter of the playfield, lane 0 press starts; when a touch starts in the second quarter, lane 1 press starts; when a touch starts in the third quarter, lane 2 press starts; when a touch starts in the rightmost quarter, lane 3 press starts; when a touch ends, that lane releases; when Enter or Space is pressed on title, song select, or results, the primary button is chosen; when R is pressed in the game screen, the current run restarts; when Escape is pressed in the game screen, the game toggles pause; when Escape is pressed in song select, it returns to title; when Escape is pressed in results, it returns to song select.

SEEDED GENERATOR: when a SONG with status ready or cleared is selected for play and it has no NOTE or AUDIO EVENT records, the generator creates them using that SONG.seed as the starting seed; if any verifier check fails, it adds 1 to the seed and regenerates until one passes. It draws random numbers with a linear congruential sequence whose state starts at the seed, each draw sets state to the remainder of state * 9301 + 49297 divided by 233280, and returns state divided by 233280. It first fills the music: for beat index b from 0 while b * SONG.beat is less than SONG.length, it creates a kick AUDIO EVENT at time b * SONG.beat when b mod 4 is 0 or 2, a snare AUDIO EVENT at the same time when b mod 4 is 1 or 3, and a hat AUDIO EVENT at time b * SONG.beat + SONG.beat / 2 when that time is less than SONG.length; drum events use length 0.05 and gain 0.8. It then creates bass events on each beat when a random draw is less than 0.75, choosing pitch from the pentatonic offsets 0, 3, 5, 7, 10, with length 0.20 and gain 0.35, and on half-beats when a random draw is less than 0.25, with length 0.10 and gain 0.25. It creates lead events on each beat with probability 0.20, 0.30, 0.40, 0.50, or 0.60 for difficulty 1 to 5, choosing pitch from the same offsets, with length 0.15 and gain 0.25, and on half-beats with probability 0.10, length 0.10, gain 0.20. It then fills the notes: starting at the first beat whose time is at least 2.0 s, difficulty 1 places one note every 2 beats, difficulty 2 places one note every beat, difficulty 3 places one note every beat plus a half-beat note when a random draw is less than 0.30, difficulty 4 uses 0.50 for the half-beat note, and difficulty 5 uses 0.70; each note gets a random lane 0 to 3, and if that lane is the same as the previous note and the time gap is less than 0.120 s, the generator moves to the next lane modulo 4. A note becomes a hold when a random draw is less than 0.00 for difficulty 1, 0.00 for difficulty 2, 0.15 for difficulty 3, 0.20 for difficulty 4, or 0.25 for difficulty 5, and a hold gets duration 0.4 to 0.8 s from a random draw; if a hold is placed, the generator blocks that lane until NOTE.time + NOTE.duration + 0.050 s and chooses the next open lane for subsequent notes, and if all four lanes are blocked the note becomes a tap in the lane that unblocks first. The verifier requires every note time to be at least 2.0 s, every note end to be at most SONG.length - 0.5 s, every lane to be 0 to 3, every duration to be 0.0 or 0.4 to 0.8 s, total notes to be at least 16 and at most 260, at least one note in each lane, no two notes in the same lane to start less than 0.120 s apart, no hold to overlap a later note in the same lane, no more than 2 notes starting within any 0.100 s window, every audio event time to be at least 0.0 s and at most SONG.length - 0.2 s, no two audio events of the same instrument to start less than 0.020 s apart, and total audio events to be at most 800; if any fails, re-roll with the next seed.

MUSIC SYNTH: when Run.status is active and Run.clock reaches an AUDIO EVENT.time whose played is false, set played true and play that instrument from INSTRUMENT pitched by the event's pitch semitones, for the event's length and gain, with the event's gain multiplied by the INSTRUMENT gain; when Run.status becomes failed or cleared, stop all future music after a 0.200 s fade; when the game is paused, suspend playback; when the game resumes, continue from Run.clock.

NOTE JUDGE: when Run.status is active and a lane press starts, search that lane for an unhit NOTE whose time is within 0.100 s before or after Run.clock, choosing the note with the smallest absolute difference between Run.clock and NOTE.time; if no such note exists, set Run.combo to 0, reduce Run.health by 1, and play a whiff sound. If a candidate note exists, set delta to Run.clock minus NOTE.time; if absolute delta is 0.030 s or less, set NOTE.judgment to perfect and NOTE.points to 100; if absolute delta is 0.060 s or less, set NOTE.judgment to good and NOTE.points to 60; otherwise set NOTE.judgment to ok and NOTE.points to 30. For a tap note with duration 0.0, set NOTE.state to hit, increase Run.totalNotes by 1, increase the matching Run counter perfectNotes, goodNotes, or okNotes by 1, increase Run.combo by 1, set Run.maxCombo to the larger of Run.maxCombo and Run.combo, set Run.multiplier to 1 plus Run.combo divided by 10 using whole numbers and capped at 5, add NOTE.points times Run.multiplier to Run.score, increase Run.health by 1 for perfect, 0 for good, and -1 for ok, and set Run.accuracy to the percentage from perfectNotes times 100 plus goodNotes times 60 plus okNotes times 30 divided by totalNotes times 100 when totalNotes is greater than 0, otherwise 100.0. For a hold note with duration greater than 0.0, set NOTE.state to holding, increase Run.combo by 1, set Run.maxCombo to the larger of Run.maxCombo and Run.combo, set Run.multiplier to 1 plus Run.combo divided by 10 using whole numbers and capped at 5, add NOTE.points times Run.multiplier to Run.score, apply the same health change for perfect, good, or ok, but do not increase Run.totalNotes or the judgment counters until the hold ends. When Run.clock reaches NOTE.time + NOTE.duration for any NOTE.state holding, set NOTE.state to held, keep NOTE.judgment, increase Run.totalNotes by 1, increase the matching Run counter by 1, add NOTE.holdBonus to Run.score, play a hold-complete sound, and update Run.accuracy. When a lane releases while a NOTE.state is holding, if Run.clock is less than NOTE.time plus NOTE.duration minus 0.050 s, set NOTE.state to missed, set NOTE.judgment to miss, increase Run.totalNotes by 1, increase Run.missNotes by 1, set Run.combo to 0, reduce Run.health by 4, and update Run.accuracy; if Run.clock is at least NOTE.time plus NOTE.duration minus 0.050 s, treat the hold as complete immediately. When Run.clock reaches NOTE.time plus 0.100 s for any NOTE.state still unhit, set NOTE.state to missed, set NOTE.judgment to miss, increase Run.totalNotes by 1, increase Run.missNotes by 1, set Run.combo to 0, reduce Run.health by 8, and update Run.accuracy. Clamp Run.health to 0 to 100 after every health change. When Run.health is 0 or less, set Run.status to failed and SONG.status to failed. When Run.status is not active, ignore all further note judgments.

SONG FLOW: when a SONG with status ready or cleared is chosen, create a RUN with that songId, set RUN.status to active, set SONG.status to active, start Run.clock at 0.0, set RUN.leadTime to 1.5, set every NOTE for that SONG to state unhit, judgment none, points 0, position 1.0, and set every AUDIO EVENT for that SONG to played false; while RUN.status is active, increase Run.clock by real elapsed seconds each frame and set each NOTE with state unhit or holding to NOTE.position equal to (NOTE.time - Run.clock) divided by RUN.leadTime, clamped to -0.200 to 1.200; when Run.clock is at least SONG.length and RUN.status is active, if Run.health is greater than 0, set RUN.status to cleared and SONG.status to cleared; when RUN.status is failed, set SONG.status to ready; when the game is paused, stop increasing Run.clock and suspend MUSIC SYNTH until unpaused; when R is pressed in the game screen, destroy the current RUN, set SONG.status to ready, and create a new RUN for the same song.

PROGRESSION: when RUN.status becomes cleared, set SONG.bestScore to the larger of SONG.bestScore and RUN.score, set SONG.bestAccuracy to the larger of SONG.bestAccuracy and RUN.accuracy, increase Player.clearedSongs by 1, add RUN.score to Player.totalScore, add RUN.totalNotes to Player.totalNotes, add RUN.perfectNotes plus RUN.goodNotes plus RUN.okNotes to Player.totalHits, set Player.bestAccuracy to the larger of Player.bestAccuracy and RUN.accuracy, and set Player.level to 1 plus Player.clearedSongs divided by 2 using whole numbers and capped at 5; then for each SONG with id equal to Player.unlockedSongs plus 1, if Player.totalScore is at least that SONG.unlockScore, increase Player.unlockedSongs by 1 and set that SONG.status to ready, repeating until the next SONG is locked or unlockedSongs is 8; when SONG.id 8 is cleared, mark the game complete by ensuring Player.clearedSongs is at least 8.

CORE LOOP: the player picks an unlocked SONG, CONTROLS turns key or touch presses into lane presses, SEEDED GENERATOR has already created the NOTE and AUDIO EVENT structure, MUSIC SYNTH plays the generated music, NOTE JUDGE converts presses into score, combo, health, and accuracy, SONG FLOW advances the clock and ends the run, and PROGRESSION adds the score to Player.totalScore, unlocks the next SONG, and records bests; each run grows totalScore, bestAccuracy, and clearedSongs, each unlock opens a harder generated song, and the win is clearing song 8, which produces the final win screen.

SCREENS: title (shows the game name, a start button, and a controls hint) → song select (shows eight SONG rows with id, difficulty, bpm, bestScore, bestAccuracy, and locked or ready status) → game (shows four lanes, falling NOTE sprites placed by NOTE.position, the hit line, and a HUD reading RUN.score, RUN.combo, RUN.maxCombo, RUN.health, RUN.accuracy, RUN.perfectNotes, RUN.goodNotes, RUN.okNotes, RUN.missNotes, and Run.clock over SONG.length) → results (shows cleared or failed, RUN.score, RUN.maxCombo, RUN.accuracy, judgment counts, and buttons for retry, next song if unlocked, and song select) → title; on title Enter, Space, or tap Start goes to song select; on song select W/S or Up/Down moves the cursor, Enter or tap starts the selected ready or cleared SONG, locked songs cannot be started, and Escape returns to title; in game Escape pauses and shows resume, retry, and quit, with Enter or tap resume continuing, R or tap retry restarting the same SONG, and Escape again or tap quit returning to song select; on results Enter or tap retry restarts the same SONG, N or tap next starts the next unlocked SONG if it exists, and M or tap menu returns to song select; after song 8 is cleared, results becomes a win screen that offers play again and title.

AUDIO: all sound is generated with the Web Audio API; when MUSIC SYNTH plays an AUDIO EVENT, it creates the named instrument sound: kick is a sine thump at 60 Hz with 0.12 s decay, snare is a noise burst centered at 1800 Hz with 0.08 s decay, hat is a square tick at 6000 Hz with 0.03 s decay, bass is a saw note pitched by the event's semitones from 55 Hz with 0.25 s decay, and lead is a square note pitched by the event's semitones from 440 Hz with 0.18 s decay; when NOTE JUDGE judges perfect, play a two-note blip at 880 Hz and 1320 Hz for 60 ms; when it judges good, play a single blip at 660 Hz for 70 ms; when it judges ok, play a single blip at 440 Hz for 80 ms; when it misses or breaks a hold early, play a low saw buzz at 110 Hz for 150 ms; when a hold completes, play a bright blip at 990 Hz for 80 ms; when a whiff occurs, play a short 220 Hz sine for 40 ms; when a UI button is chosen, play a 1200 Hz sine for 30 ms; when a SONG.status changes from locked to ready, play an arpeggio of 523, 659, 784, and 1047 Hz, each 90 ms; when a run fails, play a falling saw from 160 Hz to 80 Hz over 600 ms; when a run clears, play a rising arpeggio of 523, 659, 784, 1047, and 1319 Hz, each 120 ms.

ART: ask for a dark neon arcade stage with four glowing vertical lanes and a distant horizon as a scene for the game background; ask for a title backdrop with a large glowing marquee above the same stage as a scene; ask for a song select backdrop of a control room with four lane monitors as a scene; ask for a results backdrop of a trophy podium with four lane lights as a scene; ask for a white oval rhythm note as a sprite; ask for a long white capsule hold note as a sprite; ask for a bright starburst hit effect as a sprite; ask for a gray cracked burst miss effect as a sprite. Everything else — lane lines, note trails, the hit line, timing markers, combo text, score, health bar, accuracy, buttons, lock icons, pause menu, key labels, particles, and progress — is drawn in code.

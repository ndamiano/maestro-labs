Build this grid-based tower defense game where players place and upgrade towers to stop seeded enemy waves from reaching the base. It is made of these systems. Every number below is a given value to write into the code as-is; none of them needs checking or deriving.

SYSTEMS: GAME STATE, LEVELS, MAP GENERATOR, ENEMY WAVES, ENEMIES, TOWERS, PROJECTILES, TARGETING, ECONOMY, UPGRADES, WIN LOSE, CONTROLS, HUD, SCREENS, AUDIO, ART

GAME STATE: A single GAME_STATE record is the source of truth for session state and has fields screen, levelId, speed, paused, time. screen is one of title, game, pause, game_over, win. levelId is 1, 2, or 3. speed is 1 or 2. paused is true or false. time is seconds since level start. LEVELS, MAP GENERATOR, ENEMY WAVES, TOWERS, PROJECTILES, TARGETING, ECONOMY, UPGRADES, WIN LOSE, CONTROLS, HUD, SCREENS, AUDIO, and ART read this record for screen, level, speed, pause, and time, and no other system stores a second copy of these fields.

LEVELS: A LEVEL record is the source of truth for level parameters and has fields id, seed, width, height, waveCount, startingGold, startingLives, bossWave. The roster is Level 1 with id 1, seed 101, width 16, height 12, waveCount 10, startingGold 150, startingLives 10, bossWave 10; Level 2 with id 2, seed 202, width 18, height 12, waveCount 12, startingGold 200, startingLives 8, bossWave 12; Level 3 with id 3, seed 303, width 20, height 14, waveCount 15, startingGold 250, startingLives 6, bossWave 15. MAP GENERATOR reads width, height, seed, and id; ECONOMY reads startingGold and startingLives; ENEMY WAVES reads waveCount, bossWave, and seed; WIN LOSE reads id and waveCount; and HUD reads id and waveCount.

MAP GENERATOR: A seeded generator creates a MAP record from the current LEVEL record and has fields seed, levelId, width, height, tiles, path, spawnTileId, baseTileId. tiles is a list of TILE records with fields id, x, y, kind, pathIndex, buildable, where kind is path, buildable, or empty. The generator first places a TILE record for every grid cell with a unique id assigned in row-major order, x, y, kind empty, pathIndex -1, and buildable false. It then places the enemy path by choosing a spawn tile at the left edge and an interior y at least 2 rows from the top and bottom, choosing a base tile at the right edge and an interior y at least 2 rows from the top and bottom, extending one tile at a time only right, up, or down while staying in bounds and never revisiting a tile until it reaches the base tile, setting kind path, pathIndex in order, and buildable false on each path tile, and writing the ordered path tile ids into path. It then places buildable tiles by marking every non-path tile within Chebyshev distance 2 of any path tile as a candidate, randomly keeping 18 candidates if at least 18 exist, setting kind buildable and buildable true on those tiles, and leaving all other tiles kind empty. The MAP record is the source of truth for all map geometry, and ENEMIES read path, tiles, spawnTileId, and baseTileId; TOWERS read tiles; TARGETING reads tiles only through ENEMY positions; and HUD reads tiles for placement preview. A VERIFIER checks that path starts at spawnTileId, ends at baseTileId, has no repeated tile id, has length at least 18 and at most 40, contains only tiles inside the grid, has at least 18 buildable tiles, has no buildable tile with kind path, and has total tiles equal to width times height; re-roll with the next seed if any fails.

ENEMY WAVES: A seeded generator creates WAVE records from the current LEVEL record and has fields id, hpMultiplier, groups, active, spawned, totalEnemies, spawnTimer. groups is a list of GROUP records with fields enemyTypeId, count, interval, delay. The generator places waves in order from 1 to waveCount. It stores hpMultiplier as a given table value: wave 1 is 1.00, wave 2 is 1.10, wave 3 is 1.20, wave 4 is 1.30, wave 5 is 1.40, wave 6 is 1.50, wave 7 is 1.60, wave 8 is 1.70, wave 9 is 1.80, wave 10 is 1.90, wave 11 is 2.00, wave 12 is 2.10, wave 13 is 2.20, wave 14 is 2.30, wave 15 is 2.40. It places groups in this order: wave 1 has grunt count 5 interval 1.0 delay 0; wave 2 has grunt count 6 interval 0.9 delay 0; wave 3 has grunt count 7 interval 0.9 delay 0; wave 4 has grunt count 6 interval 0.9 delay 0 and runner count 3 interval 1.2 delay 1.5; wave 5 has grunt count 7 interval 0.8 delay 0 and runner count 4 interval 1.1 delay 1.5; wave 6 has grunt count 8 interval 0.8 delay 0 and runner count 5 interval 1.0 delay 1.0; wave 7 has grunt count 8 interval 0.7 delay 0, runner count 5 interval 0.9 delay 1.0, and tank count 2 interval 2.0 delay 2.0; wave 8 has grunt count 9 interval 0.7 delay 0, runner count 6 interval 0.9 delay 1.0, and tank count 3 interval 1.8 delay 2.0; wave 9 has grunt count 10 interval 0.6 delay 0, runner count 7 interval 0.8 delay 1.0, and tank count 4 interval 1.6 delay 2.0; wave 10 has grunt count 10 interval 0.6 delay 0, runner count 8 interval 0.8 delay 1.0, and tank count 5 interval 1.5 delay 2.0; wave 11 has grunt count 11 interval 0.6 delay 0, runner count 9 interval 0.7 delay 1.0, and tank count 5 interval 1.4 delay 2.0; wave 12 has grunt count 12 interval 0.5 delay 0, runner count 10 interval 0.7 delay 1.0, and tank count 6 interval 1.3 delay 2.0; wave 13 has grunt count 13 interval 0.5 delay 0, runner count 11 interval 0.6 delay 1.0, and tank count 7 interval 1.2 delay 2.0; wave 14 has grunt count 14 interval 0.5 delay 0, runner count 12 interval 0.6 delay 1.0, and tank count 8 interval 1.1 delay 2.0; wave 15 has grunt count 15 interval 0.4 delay 0, runner count 13 interval 0.5 delay 1.0, and tank count 9 interval 1.0 delay 2.0. When wave id equals LEVEL.bossWave, the generator appends one group with enemyTypeId boss, count 1, interval 0.4, delay 3.0. The first WAVE becomes active when the level starts, each later WAVE becomes active 5.0 seconds after the previous WAVE has no alive enemies, and when a WAVE is active its spawnTimer counts down, spawns the next enemy from the current group when it reaches 0, resets to that group's interval, starts the next group after its delay, and increments spawned for each enemy created. The WAVE record is the source of truth for wave composition and spawn state, and ENEMIES read groups and hpMultiplier, WIN LOSE reads active, spawned, and totalEnemies, HUD reads id, spawned, and totalEnemies, and AUDIO reads active. A VERIFIER checks that each wave has at least 1 group, each group count is at least 1, each interval is at least 0.4, each delay is at least 0, the final wave has a boss group, and the total enemy count across the level is at least 60; re-roll with the next seed if any fails.

ENEMIES: An ENEMY record is the source of truth for a live enemy and has fields id, typeId, hp, maxHp, speed, bounty, damage, radius, pathIndex, pathProgress, x, y, alive, slowUntil, slowFactor. The ENEMY_TYPE roster is Grunt with typeId grunt, hp 20, speed 2.0, bounty 5, damage 1, radius 0.35; Runner with typeId runner, hp 14, speed 3.2, bounty 4, damage 1, radius 0.30; Tank with typeId tank, hp 70, speed 1.3, bounty 12, damage 1, radius 0.45; Boss with typeId boss, hp 600, speed 0.8, bounty 100, damage 5, radius 0.60. When a WAVE spawns an enemy, the ENEMIES system copies the type fields into a new ENEMY record and sets hp and maxHp to the type hp times the wave hpMultiplier. The enemy moves pathProgress by speed times dt each update, uses pathIndex to read the current TILE from MAP.path and MAP.tiles, sets x and y from that tile, and while slowUntil is in the future moves at speed times slowFactor. When pathIndex is the last index of MAP.path, the enemy sets alive false and applies its damage to PLAYER.lives. TARGETING, PROJECTILES, WIN LOSE, ECONOMY, and HUD read ENEMY records for position, hp, alive, bounty, and damage.

TOWERS: A TOWER record is the source of truth for a placed tower and has fields id, typeId, tileId, gridX, gridY, level, range, damage, fireInterval, cooldown, targetEnemyId, sellValue, slowFactor, slowDuration, splashRadius, chainCount, chainRange. The TOWER_TYPE roster is Arrow with typeId arrow, cost 50, level 1 range 2.5, damage 8, fireInterval 0.5, projectileSpeed 8, sellValue1 35, level 2 range 2.8, damage 12, fireInterval 0.42, sellValue2 77, level 3 range 3.1, damage 18, fireInterval 0.36, sellValue3 147, upgradeCost1 60, upgradeCost2 100; Cannon with typeId cannon, cost 100, level 1 range 2.0, damage 18, fireInterval 1.25, projectileSpeed 5, splashRadius 0.9, sellValue1 70, level 2 range 2.2, damage 28, fireInterval 1.1, splashRadius 1.0, sellValue2 154, level 3 range 2.4, damage 42, fireInterval 1.0, splashRadius 1.1, sellValue3 280, upgradeCost1 120, upgradeCost2 180; Frost with typeId frost, cost 80, level 1 range 2.2, damage 4, fireInterval 0.83, projectileSpeed 7, slowFactor 0.5, slowDuration 2.0, sellValue1 56, level 2 range 2.4, damage 6, fireInterval 0.71, slowFactor 0.45, slowDuration 2.2, sellValue2 126, level 3 range 2.6, damage 9, fireInterval 0.63, slowFactor 0.4, slowDuration 2.5, sellValue3 238, upgradeCost1 100, upgradeCost2 160; Tesla with typeId tesla, cost 150, level 1 range 2.6, damage 10, fireInterval 0.67, projectileSpeed 12, chainCount 2, chainRange 1.8, sellValue1 105, level 2 range 2.8, damage 15, fireInterval 0.59, chainCount 3, sellValue2 217, level 3 range 3.0, damage 22, fireInterval 0.53, chainCount 4, sellValue3 385, upgradeCost1 160, upgradeCost2 240. When placement is confirmed, TOWERS creates a TOWER record on a TILE with kind buildable and no existing TOWER with the same tileId, sets level 1 stats and sellValue1 from TOWER_TYPE, sets cooldown to 0, deducts cost through ECONOMY, and sets PLAYER.selectedTowerId to the new tower id. TARGETING, PROJECTILES, UPGRADES, ECONOMY, HUD, and SCREENS read TOWER records.

PROJECTILES: A PROJECTILE record is the source of truth for a flying projectile and has fields id, ownerTowerId, targetEnemyId, lastX, lastY, x, y, speed, damage, splashRadius, chainCount, chainRange, slowFactor, slowDuration, ttl, alive. When TARGETING orders a TOWER to fire, PROJECTILES creates one projectile from the tower's current stats, sets x and y to the tower cell center, sets lastX and lastY to the target enemy's x and y, sets speed to the tower's projectileSpeed, and sets ttl to 3.0. Each update moves the projectile toward the target ENEMY's current x and y by speed times dt, updates lastX and lastY while the target is alive, and if the target is dead moves toward lastX and lastY and expires when ttl reaches 0. On reaching a point within 0.25 of an enemy, it applies damage, sets alive false, and for cannon applies splash damage to all enemies within splashRadius, for frost sets slowFactor and slowUntil on the primary target, and for tesla applies chain hits to up to chainCount other enemies within chainRange, where the first chain target takes 0.6 times the projectile damage, the second takes 0.36 times, the third takes 0.216 times, and the fourth takes 0.130 times. ENEMIES, TARGETING, ECONOMY, AUDIO, and HUD read PROJECTILE records for hit results and active projectiles.

TARGETING: TARGETING reads TOWER, ENEMY, and GAME_STATE records and has no stored copy of enemy or tower state. Every 0.1 seconds of game time, for each alive TOWER with cooldown less than or equal to 0, it selects the alive ENEMY within the tower's range that has the highest pathProgress; if no enemy is in range, it sets cooldown to 0.1 and does not fire. If an enemy is selected, it sets targetEnemyId to that enemy's id, orders PROJECTILES to create a projectile, and sets cooldown to the tower's fireInterval. If the target dies, the next targeting tick chooses a new enemy. TARGETING reads GAME_STATE.paused and does not run while paused.

ECONOMY: A PLAYER record is the source of truth for the player's resources and selection and has fields gold, lives, selectedTowerTypeId, selectedTowerId, cursorX, cursorY, lastWaveBonus. It starts with gold equal to LEVEL.startingGold, lives equal to LEVEL.startingLives, selectedTowerTypeId arrow, selectedTowerId 0, cursorX 0, cursorY 0, and lastWaveBonus 0. selectedTowerTypeId is arrow, cannon, frost, or tesla. cursorX and cursorY are integer grid coordinates. When a TOWER is placed, TOWERS deducts the tower cost from gold. When an upgrade is bought, UPGRADES deducts the upgrade cost from gold. When an ENEMY dies, ECONOMY adds its bounty to gold. When an ENEMY reaches the base, ECONOMY subtracts its damage from lives. When a WAVE finishes and lastWaveBonus is less than that wave's id, ECONOMY adds 25 gold and sets lastWaveBonus to that wave's id. When a TOWER is sold, UPGRADES adds the TOWER.sellValue to gold. WIN LOSE, TOWERS, UPGRADES, ENEMIES, WAVE, HUD, CONTROLS, and SCREENS read PLAYER for gold, lives, selection, and cursor.

UPGRADES: UPGRADES reads TOWER, TOWER_TYPE, and PLAYER records and has no separate copy of tower stats. A tower has three levels, level 1, level 2, and level 3. When the player confirms an upgrade on PLAYER.selectedTowerId, UPGRADES checks that the TOWER level is less than 3 and PLAYER.gold is at least the upgrade cost for that level; if true, it deducts the cost, increments level, copies the next level's stats from TOWER_TYPE into the TOWER record, and sets sellValue to the given sell value for that level. When the player confirms a sell on PLAYER.selectedTowerId, UPGRADES removes the TOWER record, adds TOWER.sellValue to gold, and sets PLAYER.selectedTowerId to 0. TARGETING, PROJECTILES, HUD, ECONOMY, and SCREENS read the updated TOWER record.

WIN LOSE: WIN LOSE reads GAME_STATE, LEVEL, WAVE, PLAYER, and ENEMY records and has no stored copy of lives or wave state. A level is lost when PLAYER.lives is less than or equal to 0; it sets GAME_STATE.screen to game_over. A level is won when the final WAVE has spawned all enemies and no alive ENEMY remains; it sets GAME_STATE.screen to win. If the won level is 1, the win screen offers Next Level to level 2; if the won level is 2, it offers Next Level to level 3; if the won level is 3, it offers Title. GAME_OVER offers Retry and Title. CONTROLS, HUD, SCREENS, and AUDIO read WIN LOSE results.

CONTROLS: CONTROLS reads GAME_STATE, MAP, TOWER, and PLAYER records and binds named keys and touch actions. Keyboard: W or Up Arrow moves PLAYER.cursorY up by 1, S or Down Arrow moves PLAYER.cursorY down by 1, A or Left Arrow moves PLAYER.cursorX left by 1, D or Right Arrow moves PLAYER.cursorX right by 1, with movement clamped to the map bounds. Keys 1, 2, 3, and 4 set PLAYER.selectedTowerTypeId to arrow, cannon, frost, or tesla. Enter or Space, when the cursor is on an empty buildable TILE, places the selected tower if PLAYER.gold is enough; when the cursor is on a TOWER, it sets PLAYER.selectedTowerId to that tower. U upgrades PLAYER.selectedTowerId. X sells PLAYER.selectedTowerId. Escape toggles GAME_STATE.paused in the game screen. R restarts the current level from pause or game_over. T goes to title from pause, game_over, or win. N starts the next level from win. Touch: tapping a grid cell moves PLAYER.cursor to that cell and selects a tower if one is there; tapping the arrow, cannon, frost, or tesla button sets PLAYER.selectedTowerTypeId; tapping the action button places the selected tower on an empty buildable cell or upgrades PLAYER.selectedTowerId; tapping the sell button sells PLAYER.selectedTowerId; tapping the speed button toggles GAME_STATE.speed between 1 and 2; and tapping pause, resume, restart, title, next, or retry buttons leads to the matching SCREENS action. TOWERS, UPGRADES, ECONOMY, GAME_STATE, and SCREENS read the resulting input events.

HUD: A HUD record is display state and has fields gold, lives, waveNumber, spawned, totalEnemies, selectedTowerTypeId, selectedTowerId, canPlace, canUpgrade, upgradeCost, sellValue, speed, message. It reads PLAYER for gold, lives, selectedTowerTypeId, selectedTowerId, cursorX, and cursorY; WAVE for id, spawned, and totalEnemies; GAME_STATE for speed; and TOWERS for upgradeCost and sellValue. It shows gold, lives, wave id, spawned, totalEnemies, selected tower type cost, range, damage, and fireInterval; if a tower is selected it shows its level, upgrade cost, and sell value. It draws a range circle around the cursor when selectedTowerTypeId is set and the cursor tile is buildable, and around a selected TOWER. CONTROLS, TOWERS, ECONOMY, WAVE, and SCREENS read HUD values for display.

SCREENS: The screen state machine is title → game → pause → game → game_over → title, and title → game → win → title or game. TITLE shows the game name, a Start button, and the control list; Enter, Space, or Start begins level 1 and sets GAME_STATE.screen to game. GAME shows the map, towers, enemies, HUD, and touch buttons; Escape opens PAUSE. PAUSE shows Resume, Restart Level, and Quit to Title; Enter or Space resumes, R restarts the current level, and T goes to TITLE. GAME_OVER shows waves survived, Retry, and Title; R or Retry restarts the current level, and T or Title goes to TITLE. WIN shows the level cleared, Next Level for levels 1 and 2, and Title for level 3; N or Next Level starts the next level id from the LEVELS roster, and T or Title goes to TITLE. Escape in PAUSE closes PAUSE and returns to GAME. All screens read GAME_STATE.screen and call CONTROLS actions.

AUDIO: All audio is generated with the Web Audio API and has no stored sound files. The named sounds are: click, played when any UI button or key confirmation succeeds; error, played when a placement or upgrade is denied; place, played when a TOWER is created; upgrade, played when UPGRADES increments a tower level; sell, played when UPGRADES removes a tower; arrow_fire, played when an Arrow PROJECTILE is created; cannon_fire, played when a Cannon PROJECTILE is created; frost_fire, played when a Frost PROJECTILE is created; tesla_fire, played when a Tesla PROJECTILE is created; explosion, played when a Cannon PROJECTILE reaches its target; frost_hit, played when a Frost PROJECTILE applies slow; tesla_hit, played when a Tesla PROJECTILE applies chain damage; enemy_death, played when an ENEMY hp reaches 0; enemy_leak, played when an ENEMY reaches the base; wave_start, played when a WAVE becomes active; wave_complete, played when a WAVE finishes; game_over, played when WIN LOSE sets screen to game_over; and win, played when WIN LOSE sets screen to win.

ART: Ask for dirt background tile as a tile, ask for path tile as a tile, ask for buildable tile as a tile, ask for spawn portal as a sprite, ask for base as a sprite, ask for arrow tower as a sprite, ask for cannon tower as a sprite, ask for frost tower as a sprite, ask for tesla tower as a sprite, ask for grunt enemy as a sprite, ask for runner enemy as a sprite, ask for tank enemy as a sprite, ask for boss enemy as a sprite, ask for arrow projectile as a sprite, ask for cannon shell as a sprite, ask for frost shard as a sprite, ask for tesla bolt as a sprite. Everything else — grid lines, cursor, range circles, health bars, damage numbers, buttons, text, icons, tower level badges, wave progress bars, and screen backgrounds — is drawn in code.
